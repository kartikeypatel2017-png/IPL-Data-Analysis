End-to-end EDA on 17 seasons of IPL data — from raw-data cleaning to a player performance ranking model that scores every batter, bowler, and all-rounder in the league.

## Overview

The public IPL dataset has 17 seasons' worth of real-world messiness: franchises that changed names mid-league (e.g. *Delhi Daredevils → Delhi Capitals*), the same stadium listed under five different spellings, and missing values scattered across both tables. This project turns that raw data into an analysis-ready dataset and a reusable player-scoring pipeline:

1. **Clean** — standardise team/venue names, fix dtypes, handle nulls (`notebooks/01`)
2. **Merge** — join match-level and ball-by-ball data into one table (`notebooks/02`)
3. **Analyze** — score and rank batsmen, bowlers, and all-rounders, with visualizations (`notebooks/03`)

## Cleaning Rules

- Standardised renamed franchises: RCB (Bangalore → Bengaluru), Rising Pune Supergiant(s), Delhi Daredevils → Delhi Capitals, Kings XI Punjab → Punjab Kings
- Normalised 15+ stadium name variants (e.g. `"Eden Gardens, Kolkata"` → `"Eden Gardens"`)
- Converted `date` to datetime
- Filled missing `city`, `method` (matches) and `extras_type`, `player_dismissed`, `dismissal_kind`, `fielder` (deliveries) — these are "no such event" rows, not bad data

## Scoring Model

All scores are min-max normalised to a 0–1 range so batting and bowling can be combined fairly.

- **Batting score** = 0.6 × normalised total runs + 0.4 × normalised strike rate
- **Bowling score** = 0.7 × normalised economy *(inverted — lower economy is better)* + 0.3 × normalised overs bowled
- **All-rounder score** = 0.5 × batting score + 0.5 × bowling score

> **Fix applied:** the original bowling calculation built a wickets table, computed `wickets_norm`, and then overwrote that table with a fresh `DataFrame` — silently dropping the wickets data before it was ever used. `build_bowling_stats()` in `src/player_stats.py` joins wickets back onto the final table so no data is lost.
